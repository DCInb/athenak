# DCI_3D CH-shell laser case

`DCI_3D` is the reference-informed AthenaK setup for a laser-driven open CH shell.  The
deck now encodes the requested target and drive, but an actual production launch remains
locked until a hash-matched evidence manifest proves every validation and memory gate
listed below.  The archive audit and every user-versus-reference decision are recorded in
[`REFERENCE_MAPPING.md`](REFERENCE_MAPPING.md).

## Physical setup

- Uniform three-dimensional Cartesian mesh and outflow fluid boundaries.
- CH shell density `1.1 g/cm3`, inner radius `0.8 mm`, outer radius `1.0 mm`.
- Far-side spherical cap about the `-x1` axis with a 50-degree polar half-angle
  (100-degree full cone).
- Helium ambient density `1.0e-5 g/cm3`.
- Initial common ion, electron, and radiation temperature `11,606 K` (approximately
  `1 eV`).
- Zero initial magnetic field, dual-energy MHD, Biermann battery, and Spitzer
  electron-ion exchange.
- One conservative user scalar stores `rho*Y_CH`; `Y_He=1-Y_CH`.

The interface is smoothed over `0.02 mm` radially and `0.01` in angular cosine.  Its
geometry field is a volume fraction `alpha`, while the advected scalar is a mass fraction:

```text
rho_CH = alpha rho_CH,pure
rho_He = (1-alpha) rho_He,pure
rho    = rho_CH + rho_He
Y_CH   = rho_CH/rho.
```

This distinction matters across the density contrast and preserves the initialized CH
mass under conservative scalar advection.

## Material EOS and opacity

Run `generate_reference_tables.py` to extract and convert the audited CH and He IONMIX
payloads from the local `3d_zb.zip`.  The generator rejects a mismatched archive or any
generated byte stream whose SHA-256 differs from the audited result:

| File | SHA-256 |
| --- | --- |
| `ch.2t_eos` | `b29624877c7c90ed1d8c385bef6a7882b106dd8202bf0398301e2dee09faa0d8` |
| `he.2t_eos` | `aae12f2dde296992ad630094e5755f7f52baa0816c678771e075f4848a9d63d0` |
| `ch_20g.opacity` | `47ee4b8ab3e7f249e4b7108ab5efbaabeee71bb7dd88cdea59f4b4c64738f94d` |
| `he_20g.opacity` | `1e0daba15df1a23f5f558663e867dda181886ea53b0dbad119beb6fa1215f420` |

The EOS closure uses the documented `partial_density_additive` rule:

```text
rho_CH = Y_CH rho
rho_He = (1-Y_CH) rho
e_mix  = Y_CH e_CH(rho_CH,Ti,Te) + (1-Y_CH) e_He(rho_He,Ti,Te)
Pi_mix = Pi_CH(rho_CH,Ti) + Pi_He(rho_He,Ti)
Pe_mix = Pe_CH(rho_CH,Te) + Pe_He(rho_He,Te).
```

Mixed cells share `Ti` and share `Te`.  Opacity uses partial-density, mass-weighted
additive extinction,

```text
kappa_mix = Y_CH kappa_CH(rho_CH,Te) + (1-Y_CH) kappa_He(rho_He,Te).
```

Table coordinates and positive values are geometrically interpolated.  Partial densities
created by a smoothed or numerically mixed interface can fall below a pure-material table
edge.  Opacity coordinates are clamped to the nearest valid bound.  For the EOS, specific
energy and ionization use the minimum-density surface while the trace-material pressure is
scaled linearly from that surface to zero as its partial density vanishes.  This mixed-cell
rule is testable and recovers both pure-material limits, but it is not claimed to reproduce
an unavailable FLASH mixing implementation bit-for-bit.

`run_case.py` verifies the source manifest, copies the four tables and manifest into the
owned run directory, and launches with run-relative `material_tables/...` paths.  Restarts
therefore see byte-identical tables and the same auto-recorded table fingerprints, and the
transferred run tree is self-contained.

## Twenty-group radiation

The reference boundaries are `1, 10, 50, 100, 150, 250, 400, 550, 700, 900, 1200,
1600, 2000, 2200, 2400, 2600, 2800, 3100, 3500, 4000, 10000 eV`.  Both decks use the
matching CH/He Rosseland and Planck coefficients, harmonic flux limiter with coefficient
one, and zero-energy Dirichlet radiation ghosts on every global face.

Optically thin transport uses the explicit asymptotic-preserving face flux.  The deck pins
all controls instead of relying on defaults:

```text
transport_discretization = asymptotic-preserving
ap_streaming_threshold = 0.5
ap_optical_depth_threshold = 1.0
```

The production candidate uses a documented reduced light speed
`c_hat=1.0e9 cm/s = 10 mm/ns`, about `c/30`.  Physical light speed would require at least
roughly 1.5 million global steps at this mesh spacing before tighter hydro/laser limits
and would make the requested 10 ns evolution impractical.  This RSLA is a modeling
approximation, not a numerical identity: production remains gated on matched compact
`c_hat=10` versus `30` runs, plus a shorter physical-`c` comparison where practical,
showing acceptable changes in energy, electron temperature, and radiation observables.
Opacity is never inflated to compensate for the reduced speed.

## Laser

One axial 1-omega beam (`1.053 micrometres`) supplies a square `2 TW` pulse from `0` to
`5 ns`, exactly `10 kJ` incident energy.  It uses 4,096 deterministic rays, a Gaussian
spatial profile, material-aware inverse-bremsstrahlung deposition into electron energy,
and at most one critical-surface reflection.

```text
lens center             (+1.5, 0, 0) mm
hard/Gaussian aperture  0.72 mm
target plane center     (-0.8, 0, 0) mm
target Gaussian radius  0.58 mm
```

The inner cap projects to `0.8 sin(50 deg) = 0.61284 mm`; the `0.58 mm` target radius
covers `89.5%` of that projected area.  The lens geometry supplies the requested
convergence while the straight-ray propagation option keeps the prescribed focal map
unambiguous.  The `laser` slice/full-volume outputs contain path length, optical depth,
segment count, and deposited-power fields for ray/deposition visualization.

## Mesh and output cadence

The first memory-calibration candidate is `400 x 256 x 256` cells with `50 x 32 x 32`
MeshBlocks: `8 x 8 x 8 = 512` blocks, exactly 64 blocks per rank on eight GPUs.  It
resolves the shell thickness with approximately 23--26 cells.  This is a calibration
candidate, not evidence that the 60--80 percent requirement has passed.

History is written every `0.025 ns`.  Its 20 reductions include laser deposited energy
and power, outward radiation power, total/CH mass, material/kinetic/magnetic/ion/electron
energies, total and three broad-band radiation energies, matter-plus-radiation energy,
integrated `|B|`, laser/radiation x-centroid numerators, mixed mass, and x momentum.
Integrating `rad_Pesc` permits the chain-energy budget to include radiation boundary loss.
All 20 individual group fields remain available in `mhd_3t` outputs.

Central `x1-x2` and `x1-x3` fluid/3T/laser slices are written every `0.1 ns`.
Full-volume fluid/3T/laser fields are written every `0.5 ns`, and restarts every `1 ns`.
Full-volume I/O caused the previously observed long pauses after hundreds of steps; it is
sparse here by design.  Reassess storage and I/O time before production.

## Safe workflow

The launcher uses the local AthenaK MPI/CUDA/Volta build helper and requires exactly eight
unique GPUs.  It rejects occupied GPUs unless explicitly allowed, refuses to clean a
directory without its ownership sentinel, and never launches production merely because a
command-line override was supplied.

Print build and compact initialization commands without changing state:

```bash
python3 DCI_3D/run_case.py --build --mode validate --dry-run
```

Build and check table loading plus initialization on a compact `2 x 2 x 2` block mesh:

```bash
python3 DCI_3D/run_case.py --build --clean --mode validate
```

The default smoke mode advances 50 RK2 steps, crosses history/slice/restart boundaries,
then restarts for ten more cycles with the same table copies/fingerprints:

```bash
python3 DCI_3D/run_case.py --clean --mode smoke
```

Measure the full candidate allocation for two steps:

```bash
python3 DCI_3D/run_case.py --clean --mode calibrate
```

Calibration returns status 2 unless every GPU's measured allocation increase is between
60 and 80 percent of its total memory.  Tune the uniform mesh and repeat if it misses.

## Production gate and 5+5 ns staging

An actual `--mode production` call requires local `DCI_3D/production_gate.json`.  The file
is ignored by Git and must use schema 1.  Its `artifacts` mapping must exactly match the
launcher's current binary, problem generator, both decks, launcher, and all four audited
tables.  Each required check must be `passed: true` and cite at least one existing evidence
file with a matching SHA-256:

```json
{
  "schema": 1,
  "artifacts": {"... exact output of the validated launcher ...": "..."},
  "checks": {
    "compact_20group_50step": {
      "passed": true,
      "evidence": [{"path": "runs/smoke/run_status.json", "sha256": "..."}]
    }
  }
}
```

The exact required check names are:

- `compact_20group_50step`
- `compact_output_and_restart`
- `finite_nonnegative_3t`
- `causal_timestep_no_collapse`
- `laser_and_boundary_energy_closure`
- `ch_mass_conservation`
- `restart_continuity`
- `resolution_or_opacity_sensitivity`
- `reduced_light_speed_sensitivity`
- `gpu_memory_60_80_all`

The evidence must show finite, nonnegative ion/electron/group energies; a timestep of
order `dx/c` without secular collapse; 10 kJ incident and laser power closure; chain-energy
closure including integrated outward radiation; CH-mass conservation; continuous restart
time/timestep/energies; a doubled-resolution or opacity-sensitivity result; acceptable
`c_hat=10`/`30` (and short physical-`c`) sensitivity; and 60--80 percent memory on all
eight V100s.

Only after that manifest validates does phase 1 evolve to the aligned `5 ns` checkpoint.
Phase 2 restarts the exact checkpoint, leaves the square pulse naturally off at `t>=5 ns`,
and evolves to `10 ns`.

Print those intended commands without satisfying or bypassing the gate:

```bash
python3 DCI_3D/run_case.py --mode production --dry-run
```

## Output transfer

The intended staging tree is local ignored `DCI_3D/run`.  The dedicated non-deleting
`tranfile_config.json` recursively transfers it to `~/data/DCI_3D` on the configured host.
Validate and then start the watcher from the repository root:

```bash
mkdir -p DCI_3D/run
python3 /home/mengqi/Research/TranFile/file_watcher.py \
  --config DCI_3D/tranfile_config.json --validate-only
python3 /home/mengqi/Research/TranFile/file_watcher.py \
  --config DCI_3D/tranfile_config.json
```

Do not use the unrelated global TranFile configuration: it can delete source `.bin` and
`.rst` files.  The DCI configuration waits for four unchanged size/mtime checks, keeps
separate logs/state, and retains every local file after transfer.

Electron heat conduction from the archive is not enabled in this first case because a
material-aware conduction implementation is not yet available.  The archived Au cone and
DT layers are deliberately omitted because they conflict with the requested all-CH shell.
